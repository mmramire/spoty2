# Reglas de Integración con la API de Spotify (rules.md)

Estás ayudando a construir una aplicación utilizando la API Web de Spotify. Sigue estrictamente las siguientes directrices:

- **Especificación OpenAPI**: Consulta la especificación OpenAPI de Spotify en https://developer.spotify.com/reference/web-api/open-api-schema.yaml para conocer todas las rutas de endpoints, parámetros y esquemas de respuesta. No adivines endpoints ni nombres de campos.
- **Autorización**: Utiliza el flujo de Código de Autorización con PKCE (https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow) para cualquier dato específico de usuario (como tu biblioteca de 3,084 canciones). Si la aplicación cuenta con un backend seguro, también es aceptable el flujo estándar de Código de Autorización (https://developer.spotify.com/documentation/web-api/tutorials/code-flow). Utiliza "Client Credentials" únicamente para datos públicos que no pertenezcan a usuarios. **Nunca utilices el flujo "Implicit Grant"** (está obsoleto).
- **URIs de Redirección**: Utiliza siempre URIs de redirección con HTTPS (excepto `http://127.0.0.1` para desarrollo local). **Nunca utilices `http://localhost` ni URIs con comodines**. Consulta los requisitos en https://developer.spotify.com/documentation/web-api/concepts/redirect_uri.
- **Scopes (Permisos)**: Solicita únicamente los scopes mínimos necesarios para las funcionalidades que se estén construyendo en cada momento (https://developer.spotify.com/documentation/web-api/concepts/scopes). No solicites permisos amplios por anticipado.
- **Gestión de Tokens**: Almacena los tokens de forma segura (en este proyecto, localmente en `data/tokens.json` con permisos restrictivos). Nunca expongas secretos de cliente en código del lado del cliente. Implementa la lógica de refresco de tokens (https://developer.spotify.com/documentation/web-api/tutorials/refreshing-tokens) y reenvía al usuario a través del flujo de autorización si el token de refresco expira.
- **Límites de Velocidad (Rate Limits)**: Implementa retroceso exponencial (*exponential backoff*) y respeta la cabecera `Retry-After` al recibir respuestas HTTP 429. No reintentes de inmediato ni en bucles cerrados.
- **Endpoints Obsoletos**: No utilices endpoints obsoletos. Prefiere `/playlists/{id}/items` en lugar de `/playlists/{id}/tracks`, y utiliza `/me/library` en lugar de los endpoints de biblioteca específicos por tipo.
- **Manejo de Errores**: Maneja todos los códigos de error HTTP documentados en el esquema OpenAPI. Lee el mensaje de error devuelto y utilízalo para proporcionar retroalimentación significativa al usuario o registrarlo en `data/app.log` mediante Pino.
- **Términos de Servicio para Desarrolladores**: Cumple con los Términos de Desarrollador de Spotify (https://developer.spotify.com/terms). En particular: no caches contenido de Spotify más allá de lo necesario para su uso inmediato, atribuye siempre el contenido a Spotify y no utilices la API para entrenar modelos de aprendizaje automático con datos de Spotify.
